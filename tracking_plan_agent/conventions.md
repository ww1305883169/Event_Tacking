## R1 指标名 ⏳

- 格式：`【功能/迭代名】+ 具体入口/模块名`
- 功能名用全角方括号【】标记，如 `【场景选择页迭代】模式选择入口`

## R2 指标描述 ⏳

- 格式：`名词短语 + uv/pv`，多条指标换行分隔
- 点击类与曝光类分别成行，如：
  ```
  入口点击uv/pv
  入口曝光uv/pv
  ```

## R3 事件列 ⏳

信息密度最高的列，固定语法顺序：

1. **平台事件链接**：已有事件直接引用 `http://ping.migu.cn/apex/#/ameta/add-event/xxx`；
   新事件输出 `【待建事件：建议事件名】` 占位，待平台建好后回填
2. **页面/组件定位**：`页面/组件` 格式，如 `畅听播放器/按钮`
3. **上报要求**：如 `曝光和点击都要报`
4. **参数列表**：以 `参数：` 关键字引出，每个参数一行 `参数名 + 赋值规则`

## R4 参数赋值规则四型 ⏳

生成每个参数时必选其一并明确标注：

| 类型 | 语法示例 | 使用场景 |
|---|---|---|
| 写死型 | `写死 "模式入口"` | 固定 UI 文案/位置标识 |
| 枚举型 | `（歌曲:"2"，MV:"D"）` | 有限资源类型/模式集合，中文键映射上报值 |
| 动态型 | `当前播放内容的id` | 运行时取值 |
| 默认型 | `默认传"default"` | 可空兜底 |

## R5 端 ✅（范围）/ ⏳（写法）

- 多端并列用顿号分隔
- 历史写法：`Android、IOS、鸿蒙`（注意 `IOS` 是团队习惯写法，非标准 iOS）
- 端范围不限于三端，还包括：**Web、小程序、服务端** 等，以需求文档中的标注为准
- ⏳ 待与飞书规范确认：`Web`/`web`、`小程序`、`服务端` 的确切写法

## R6 触发类型 ⏳

- 与事件列上报要求严格一致：`都要报` ↔ 触发类型写 `点击、曝光`
- 顿号分隔

## R7 截图说明 ✅

- 历史表用 WPS `=DISPIMG("ID_xxx",1)` 嵌入截图，agent 无法读取图片
- agent 生成时输出占位 `【待补截图】`，由人工嵌入
- 注意：回写 Excel 时不得破坏已有 DISPIMG 公式与嵌入图片（见 SKILL.md 写回安全规则）

## R8 复用与查重 ✅

- 生成前必须在**全量埋点表**（`data/all_events.xlsx`）与 `corpus/` 中检索相同/相似事件
- 已有相同事件：直接引用原平台链接，并在事件列首标注 `复用已有事件`
- 相似但需变更：引用原链接 + 说明差异（新增参数/改触发等）
- 完全新事件：`【待建事件：建议事件名】` 占位

## R9 安全 ⏳

- 参数中禁止出现 PII 等敏感字段（手机号、设备号明文等）
- ⏳ 待与飞书规范确认：敏感字段白名单/黑名单口径
