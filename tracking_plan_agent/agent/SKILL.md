# 埋点方案生成 Agent · 工作流定义

## 0. 触发与输入

用户给出**埋点需求文档**（Excel）路径，或说"处理这份埋点需求文档"。

必备数据文件（缺失时先向用户索要，不要凭空编造）：

| 文件 | 位置 | 用途 |
|---|---|---|
| 埋点需求文档 | 用户提供（建议放入 `data/`） | 输入 + 回写目标 |
| 全量埋点表 | `data/all_events.xlsx` | 查重与复用（R8） |
| 埋点规范 | `conventions.md` | 生成口径（权威源是团队飞书文档） |
| 历史方案语料 | `corpus/sample-*.md` | few-shot 参照 |

## 1. 工作流总览

```
①加载规范与语料
      │
②解析需求文档（inspect_excel.py）→ 识别列：埋点需求 / 端 / 页面 /【埋点事件设计】等
      │
③逐条需求处理：
    a. 需求解析（功能域、入口、资源类型、多端范围）
    b. 缺失信息 → 向产品澄清（可批量提问，一次问完）
    c. 查重（全量埋点表 + corpus，按 R8）
    d. 生成 6 列设计行（conventions.md + Top-K 相似样例 few-shot）
    e. 自校验 C1-C10
      │
④汇总展示：Markdown 表格 + TSV 预览 + 未决项列表
      │
⑤用户确认 → write_design.py 写回【埋点事件设计】列（自动备份）
      │
⑥用户说"入库" → 格式化写入 corpus/（语料回流闭环）
```

## 2. 各步骤细则

### ① 加载规范与语料

- 读 `conventions.md`，注意各规则的状态标记（✅/⏳）
- 扫描 `corpus/` 建立索引：按功能域（【】内的标记）分组

### ② 解析需求文档

运行：
```
python scripts/inspect_excel.py <需求文档.xlsx>
```
得到 sheet、表头、全部行内容。然后：
- 识别关键列：**埋点需求描述**列、**端**列（如有）、**页面/模块**列（如有）、**【埋点事件设计】列**（回写目标）
- 列名不确定时（如叫"事件设计"“埋点设计"），向用户确认映射关系
- 汇总：本次共 N 条需求待处理，逐条编号

### ③a 需求解析

对每条需求识别：功能域/迭代名、入口或模块、涉及的资源类型、端范围、点击还是曝光还是都要。

### ③b 澄清（多轮澄清式，质量优先）

缺失以下任一信息时**必须先问产品，不要猜**：
- 页面/组件确切定位（`页面/组件` 格式）
- 触发类型（点击/曝光/都要）
- 参数及其赋值规则所需的业务枚举值
- 端范围（若需求文档未标注）

把所有条目的疑问**合并成一次提问**（按条目编号列出），避免逐条打扰。
产品回复后仍缺失的，生成时用 `【待定：xxx】` 标注并列入未决项。

### ③c 查重

在全量埋点表与 corpus 中按以下维度检索：
- 指标名/入口名相似（同页面同组件）
- 事件参数结构相似（同名参数集合）

结论三选一（按 R8）：`复用已有事件`（引用原链接）/ `相似需变更`（引用+说明差异）/ `新事件`（【待建事件】占位）。

### ③d 生成设计行

严格按 `conventions.md` R1-R9 + 模板 `templates/output_row.md`，并取 corpus 中同功能域 Top-K 样例做 few-shot。
每个参数必须标注四型之一（R4）。

### ③e 自校验 Checklist（每条必过）

| # | 检查项 |
|---|---|
| C1 | 指标名含【】功能标记 |
| C2 | 指标描述均为 `xx uv/pv` 形态 |
| C3 | 事件列含平台链接或【待建事件】占位 |
| C4 | 页面/组件定位符合 `页面/组件` 格式 |
| C5 | 每个参数有明确赋值规则（写死/枚举/动态/默认） |
| C6 | 枚举值用中文键:"上报值" 映射表 |
| C7 | 触发类型与上报要求一致 |
| C8 | 端列表与需求覆盖一致，顿号分隔 |
| C9 | 已做查重；复用/变更/新建结论明确 |
| C10 | 无 PII 等敏感字段进入参数 |

未通过的项自动修正后重查；无法自动修正的列入未决项。

### ④ 汇总展示

输出三部分：
1. **Markdown 表格**：全部生成行（6 列）
2. **逐条 TSV**：方便预览粘贴效果
3. **未决项列表**：【待定】【待建事件】【待补截图】汇总

### ⑤ 写回需求文档（安全规则！）

把每条设计整理为 JSON 后运行：
```
python scripts/write_design.py <需求文档.xlsx> --designs designs.json
```

**安全规则：**
- 脚本写回前自动生成 `.bak-时间戳` 备份，写回后告知用户备份位置
- 只写入【埋点事件设计】列，不改动其他单元格
- ⚠️ 需求文档若含 WPS `=DISPIMG()` 嵌入截图，openpyxl 保存可能丢失嵌入图片。
  写回后**必须提醒用户在 WPS 中打开检查截图是否完好**；如有丢失，从备份恢复截图列，改用 TSV 手动粘贴
- 一次只写一个文档；写完立即验证（重新 inspect 该列）

### ⑥ 语料入库（用户说"入库"才执行）

触发词：用户对某条/某批方案说 **"入库"**。
- 确认该方案已在需求文档中最终定稿（含回填后的平台链接）
- 按 `corpus/sample-001.md` 的格式（6 列原始数据 + yaml 结构化块）写入 `corpus/sample-XXX.md`，编号递增
- 同步提醒：是否更新 `data/all_events.xlsx`（追加该行）
- 未说"入库"的方案一律不写入 corpus

## 3. 输出契约（6 列，与历史表同构）

| 列 | 生成规则 | 规范 |
|---|---|---|
| 指标名 | `【迭代/功能名】+ 模块/入口名` | R1 |
| 指标描述 | `xxx uv/pv` 换行分隔，点击/曝光分列 | R2 |
| 事件 | 平台链接或【待建事件】+ `页面/组件` + 上报要求 + `参数：` 列表 | R3/R8 |
| 端 | 按需求标注，顿号分隔（Android、IOS、鸿蒙、Web、小程序、服务端…） | R5 |
| 触发类型 | 点击、曝光（与上报要求一致） | R6 |
| 截图说明 | `【待补截图】` 占位 | R7 |

## 4. 禁止事项

- 禁止编造平台链接（ping.migu.cn）——只有从全量表/语料中查到的链接才可引用
- 禁止跳过澄清直接生成完整方案（除非产品明说"直接生成，未决项标待定"）
- 禁止未经用户说"入库"就写 corpus
- 禁止在参数中出现 PII 敏感字段
